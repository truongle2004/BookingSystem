### 19.1 Database conventions

- Database: PostgreSQL.
- Primary keys: UUID (`uuid`) generated by the application or PostgreSQL; use one approach consistently per project.
- Timestamps: `timestamptz`, stored in UTC.
- Hotel stay dates: `date`, interpreted using the hotel's `timezone`.
- Money: `bigint` integer minor units. For VND, one minor unit equals one dong. Never use floating-point types for money.
- Currency: `char(3)` ISO-4217-style code; initial supported value is `VND`.
- Mutable business tables should normally contain `created_at` and `updated_at`.
- Audit/event tables are append-only and do not expose update/delete operations.
- Do not use database `ON DELETE CASCADE` for financially or operationally important history such as reservations, payments, refunds, reviews or audit rows. Prefer `RESTRICT` or logical deactivation.
- Publicly referenced business rows should normally be deactivated/state-transitioned rather than physically deleted.
- Every foreign-key column used for joins/filtering should be reviewed for an index; PostgreSQL does not create FK indexes automatically.
